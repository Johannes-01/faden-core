# Changelog

The `public` API of `FadenCore` and `FadenTranscription` is the contract with the Faden app. Versions follow [semantic versioning](https://semver.org); until 1.0, a minor version may change that API, and a patch version never does.

## Unreleased

## 0.6.0 - 2026-11-02

- The notes header links the Faden website: `> Generated by [Faden](https://johannes-01.github.io/Faden-website/) on …`. `NotesHeader.websiteURL` holds the URL; `NotesHeader.firstLinePrefixes` lists how the first line starts in old and new notes, for readers that recognize the header.
- Flashcards (`Flashcards`): one call over a lecture's notes (not the transcript) for exam-style questions with answers, each keeping the source label its answer rests on. `Flashcards.request(notes:examples:model:)` can take past exam questions as style examples; `markdown(…)` writes `flashcards.md` (one `## n. question` per card, the answer and label below), `read(_:)` reads it back, `csv(_:tags:)` exports `Front,Back,Tags` for Anki.
- Study guides (`StudyGuide`): one call over a course's lectures' notes for a guide by topic, with an exam checklist and open questions. Its `lecture:L<n>#<heading>` links become `faden:lecture?path=<folder relative to the course>&heading=<heading>` (`StudyGuide.lectureLink`), and the header lists the lectures. Written to `Study guide <date>.md` in the course folder, never over an earlier one.
- `StudyMaker` sends either call, records it in the cost ledger as the new steps `flashcards` and `studyGuide` (`CostRecord.Step`), and writes the file. `NotesHeader.cost(of:)` formats a Cost line for any calls.
- `faden flashcards <lecture folder> [--notes file] [--examples file] [--csv]` and `faden study-guide <course folder> [--lectures …]`, both with `--model` and `--subscription`.
- Fix: a `--json-schema` reply through the `claude` CLI is no longer taken for a cut-off one. The CLI answers through its `StructuredOutput` tool, so a `user` event with the tool result follows the reply; since 0.4.0 that counted as a resume after the output limit, so on the Claude subscription the check (and any structured call) failed as "cut off" and was skipped.

## 0.5.0 - 2026-11-02

- The check model can be chosen too: `Pipeline(…, checkModel:)` (default `Verifier.model`, Haiku 5.5) and `Verifier.request(…, model:)`.
- `PipelineState` records `notesModel` and `checkModel`. A run fills in the pipeline's models where the state names none, so a retry asks the same models as the run it continues. Both are optional: `state.json` files saved before decode with nil, which means the pipeline's models. `PipelineState.init` and `ReprocessRequest` take them too (`ReprocessRequest.notesModel`, `.checkModel`, nil by default).
- `carryingPaidDraft(from:)` reuses a paid draft only when it was written by the same notes model, and its check only when the check model is the same too; with a new check model, Process again only runs the check.
- `NotesHeader(…, checkModel:)` names the chosen check model when the check made no call.
- `faden process` and `faden retry` take `--check-model haiku|sonnet|opus`. `faden retry` keeps the models saved in the run's state.
- `Pipeline.init`, `PipelineState.init`, `NotesHeader.init` and `Verifier.request` gained a parameter with a default, so existing calls compile unchanged; binary-wise they are new, hence the new minor version.

## 0.4.0 - 2026-11-02

- The notes model can be chosen: `NotesInputs.model` and `Pipeline(…, notesModel:)`, both defaulting to `NotesPrompt.model` (Opus 5.5). The check stays on Haiku 5.5. Both initializers gained the parameter with a default, so existing calls compile unchanged; binary-wise they are new initializers.
- `faden process` and `faden retry` take `--notes-model opus|sonnet|sonnet-5` (`sonnet` is Sonnet 5.5). Haiku 5.5 is not offered for notes: on a full lecture it spends almost all of its output on thinking and runs past the output limit (#6). It still does the check.
- `Pricing` knows `claude-sonnet-5-5` and `claude-sonnet-5` (both $2 / $10 per MTok; cache reads $0.10 and $0.20).
- Fix: `ClaudeCLIClient` reports a reply the `claude` CLI resumed after the output limit as `AnthropicError.truncated`. The CLI asks the model to "resume directly" on its own and then returned only the last part as a success, so `--subscription` runs could save cut-off notes as complete (#6).

## 0.3.0 - 2026-10-30

- Each `costs.jsonl` line now also records the pipeline `step` (`notes` or `verify`), the `provider` (`anthropic`), the `billing` (`api` or `subscription`) and `apiUSD`, what the call costs with an API key even when it ran on the subscription. `usd` still holds what was paid. Older lines decode with these fields as nil.
- `CostRecord(date:lecture:step:call:)` builds a record from a `PaidCall`; `CostLedger.apiTotal(since:)` sums the API prices, pricing older lines from their tokens; `Pricing.provider(model:)` names a model's provider.
- Ledger lines have their keys sorted, so every line has the same order.
- `scripts/cost-report.swift` counts runs by `step` where a line has it.

## 0.2.0 - 2026-10-29

- `Library` scans course folders and their subfolders into lectures with status, notes, transcript, slides, length, cost and iCloud state; `CourseList` keeps the course folders as bookmarks.

## 0.1.0 - 2026-10-29

First release as its own package, split out of the Faden app.

- Library products `FadenCore` (pipeline, prompts and styles, Anthropic API and `claude` CLI clients, Keychain, verification and output) and `FadenTranscription` (on-device transcription with WhisperKit).
- New `faden` command-line tool: `faden process`, `faden retry` and `faden styles` run the whole pipeline without the app.
- The resource bundle is now `faden-core_FadenCore.bundle` (it was `Faden_FadenCore.bundle`); `FadenCore.resourceBundleName` is public, so an app can find it.
